## 2. 能力地图（全部经真机验证）

### 2.1 跨文件理解
| 能力 | 说明 |

### 2.2 静态检查（5 项，零误报）
| 检查项 | 判定依据 |
|---|---|
| 未使用导入 | import 名（含 as 别名、点号首段）在 Load 上下文 0 次引用 |
| 重复定义 | **同一作用域**内同名 def/class 多次出现（不同类里的同名方法属合法重写，不报）|
| 空实现 | 函数/类体去掉 docstring 后只剩 pass |
| 未使用变量 | 简单名目标赋值后在整个函数子树内从未被读取（跳过 _ 前缀、global/nonlocal）|
| 未定义名字 | Load 上下文中出现且不在「builtins ∪ dunder ∪ 导入 ∪ 定义 ∪ 参数 ∪ 赋值目标 ∪ global/except」白名单内 |

配套：**问题视图**（常驻工具窗）· 运行检查（全工程 / 仅当前文件）· 类型筛选 · 按严重性/名称排序 · 点行跨文件跳转 · 保存后自动检查 · 编辑器 **gutter 琥珀警示标**。

## 3. 验证方法（可复现）

每次交付都要求**双断言**：组件级证据 + 人类可读证据。

| 通道 | 用法 |
|---|---|
| 组件 id | 关键控件带 .id()（tb-run/debug/stop/moreRun/ai/searchEverywhere/settings、sw-query 等），用 uitest dumpLayout 按 id 取坐标 |
| 文本锚点 | 按文本精确取坐标（菜单项、按钮、结果行）|
| 日志断言 | 应用自检写入 hilog：`selfcheck seFirst=… seActions=…`（入口可达性）等 |
| 截图 | `snapshot_display` 存 JPEG，人工/模型看图确认视觉结果 |
| 状态栏断言 | 每次动作的状态提示（如「检查完成：7 条」「已插入补全：utils.fib」）|

验证脚本位于 `_cache/device/*.py`（每次运行生成唯一文件名，避免缓存干扰）。

## 4. 已知边界（如实列出）

- **键盘输入**：设备自动化无法向应用输入框注入文本（uitest 限制），因此补全/重命名等以**对话框 + 点击**形式提供同等能力；
- **剪贴板**：HarmonyOS 隐私限制，应用读不到系统剪贴板，「与剪贴板比较」入口保留但会诚实提示；
- **git**：设备无 git 可执行文件，VCS 相关只做到「变更时间线」（本地历史聚合），未做提交/分支/推送；
- **外部系统**：Maven/Gradle 式构建系统集成未做（设备无对应工具链），只做任务执行与依赖清单；
- **补全**：为文件/模块级（非类型推断），不支持 `obj.` 成员推断；
- **作用域视图菜单**：ScopeViewPopupMenu 的 41 项菜单（查找用法/重构/按作用域分组）依赖语义索引，未实现。

## 5. 架构要点

- **运行时 Python 通道**（本项目的关键基础设施）：把分析脚本写入应用私有目录 → 调用内置 CPython 执行 → 结果写文件 → 应用**轮询读取**。
  要点：`run` 返回 ≠ 写入完成；启动期还要处理「运行时尚未初始化」（本项目实现了 500ms 重试，最多 ~10s）。
- **工程整洁**：所有中间产物（历史快照、分析输出、重命名备份）都放在应用私有目录 `${filesDir}/.harmonyide`，工程目录保持干净（并在启动时清理历史遗留）。
- **示例工程自愈**：示例文件按「存在性 + 版本标记」创建/重建，既能给用户一个可用示例，也充当各功能的真机验证样本。
